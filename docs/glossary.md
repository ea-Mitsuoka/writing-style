# 用語集

このプロジェクト固有の共通言語。コードの識別子・ドキュメント・会話で、1 つの概念に 1 つの
用語を使う（COD-002）。基盤の再利用語は `docs/foundation/glossary.md` を先に確認する。

## 用語

| 用語 | 定義 | 文脈 | 使わない語 | 混同しないもの |
| -- | -- | -- | -- | -- |
| Vault | 表現ルールの本文を置くメモリリポジトリ `ea-Mitsuoka/ai-memory`。本リポジトリは読むだけで書かない | rules | メモリ、保管庫 | このリポジトリ（仕組みだけを持つ） |
| 表現ルール | Vault の `30_memory/feedback/ja-<kind>-<slug>.md` に置かれた、日本語の表現・用語に関する 1 件の規則。`feedback` 型の派生 | rules | スタイルルール、文章ルール、writing rule | 文体規則（表現ルールの種別の 1 つ） |
| 種別（kind） | 表現ルールの分類。`term`（用語固定）/ `style`（文体規則）/ `structure`（構造規則）の 3 値。コード識別子は `kind` | rules | タイプ、カテゴリ | scope（適用範囲） |
| 適用範囲タグ（scope tag） | 表現ルールが効く文書の種類を示すタグ。`customer-doc` / `decision-doc` / `internal-doc` / `slide` / `chat` / `code` の 6 値で、語彙の正典は Vault `AGENTS.md`。コード識別子は `scope` | rules | コンテキスト、対象、target | kind（種別） |
| NG / OK 例 | 表現ルール本文の `## NG / OK` 節にある、指摘された表現と修正後の表現の対 | rules | 悪い例 / 良い例、before / after | 検証結果（このモジュールの出力） |
| 検証結果（finding） | 検証モジュールが 1 つの書式違反について出す 1 行の報告。相対パス・コード・メッセージからなる。コード識別子は `Finding` | rules | エラー、警告、指摘 | 指摘（人が AI の日本語に対して行う修正の要求） |
| 指摘 | 人が AI の書いた日本語に対して行う修正の要求。表現ルールの元になる | rules | フィードバック、レビューコメント | 検証結果 |
| 安定ルール | `updated` が一定期間（目安 60 日）更新されていない表現ルール。Skill 等へ昇格できる | rules | 確定ルール、固定ルール | — |
| セッション記録（transcript） | Claude Code が `~/.claude/projects/<プロジェクト>/<セッション ID>.jsonl` に残す対話の記録。1 行 1 レコードの JSON | extraction | ログ、履歴、チャット履歴 | claude.ai のエクスポート（別の製品の別形式） |
| 候補（candidate） | 抽出モジュールが指摘の可能性ありと判定した、人間の発話 1 件と直前の assistant 本文の対。スコアと一致キーワードを持つ。コード識別子は `Candidate` | extraction | ヒット、マッチ、結果 | 指摘（人が確定したもの）、表現ルール（ルール化後） |
| 候補一覧 | 抽出モジュールが書く 1 ファイル `out/candidates-<YYYYMMDD>.md`。候補をスコア順に並べ、先頭に走査の統計を置く。人名・案件名を含み得るため commit も共有もしない | extraction | レポート、出力、結果ファイル | 候補（一覧の 1 項目） |
| 仕分け（triage） | 候補一覧を人と AI が読み、日本語表現への指摘か否かを判定し、指摘をルール化する工程。確定は利用者が行う | extraction | レビュー、分類、選別 | 検証（`rules` モジュールの書式検査） |
| 強キーワード / 弱キーワード | 候補のスコアに使う語句。強は指摘を強く示す語（わかりづらい・不自然・言い回し・表現・AIっぽい・揺れ、各 3 点）、弱は作業指示にも多い語（ではなく・直して・言い換え、短い発話で各 1 点）。`#表現` タグは 10 点。値は `docs/requirements/extraction.md` FR-106 が正典 | extraction | 検索語、シグナル | scope タグ（表現ルールの適用範囲） |

## 解決した曖昧さ

命名の衝突とその解決の追記専用ログ。

- 「指摘」が、人からの修正要求と検証モジュールの出力の両方を指していた。2026-09-18 に解決:
  人からのものを「指摘」、モジュールの出力を「検証結果（finding）」とする。
